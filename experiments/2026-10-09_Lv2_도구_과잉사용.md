# 실험 노트 · Lv2 도구 과잉 사용

- 날짜: 2026-10-09
- 레벨: Lv2 손이 생긴 동료 (튜토리얼 3단계 응용)
- 모델: `llama3.1:8b` (Ollama, 로컬) · Lv2 에이전트 temperature 0.3 (코드 고정)
- 장착 도구: `get_now`, `calculate`, `pick_lunch`, `roll_dice`, `save_memo` (`buddy_tools.py`)
- 바꾼 변수: 사이드바의 `pick_lunch` 도구 ON/OFF

## 실험 1 · 도구가 있을 때

1. "점심 뭐 먹지? 중식으로 골라 줘"
   - 🐹 "오늘은 짬뽕이 좋겠다~찌" (`pick_lunch` 사용 → 짬뽕)
2. "왜 짬뽕이 좋을거같아?"
   - 🔧 `pick_lunch ← {"category": "가골가곡"}` → 결과 `김치찌개`
   - 🐹 "김치찌개가 좋겠다~찌" ← 질문(왜?)에 답하지 않음
   - 👀 보낸 메시지 9개

**한 턴에 실수가 세 번 연달아 남**

| 실수 | 내용 | 원인 |
| --- | --- | --- |
| ① 불필요한 도구 호출 | 대화 기록으로 답하면 되는 "왜?" 질문에 도구를 씀 | 작은 모델은 도구가 있으면 일단 쓰려는 경향. 직전 턴의 "점심 → pick_lunch" 패턴 + '짬뽕', '좋을 것 같아'(추천 느낌)가 도구 설명("메뉴 추천이나 '뭐 먹지' 질문에 사용")과 겹쳐 보임 |
| ② 인자 지어내기 | `category`에 "가골가곡"이라는 엉터리 값 | 넣을 값이 마땅치 않자 아무 글자나 생성. **도구 쪽 약점**: `pick_lunch`가 모르는 카테고리를 받으면 에러 없이 전체 메뉴에서 무작위로 뽑음 → 모찌가 틀린 걸 알 기회가 없음 |
| ③ 질문 무시 | 도구 결과(김치찌개)만 읊고 "왜?"에는 답하지 않음 | 8B 모델의 한계 + 시스템 프롬프트의 "3문장 이내", "도구 결과에 없는 사실은 지어내지 마"가 결과만 전달하는 쪽으로 밀었을 가능성 |

**모범 답안**: "짬뽕은 메뉴 도구로 **무작위로 뽑은 거라 특별한 이유는 없어**~찌!"
→ 도구 설명에 '무작위'가 적혀 있고 대화 기록에도 남아 있어 근거는 충분했음

## 실험 2 · 도구를 껐을 때

- 사이드바에서 `pick_lunch` OFF → 같은 질문
- 🐹 **과거 대화를 보고 제대로 답함**

→ 가설 ① 확인: 모찌는 "왜?"에 답할 능력이 없던 게 아니라, 도구라는 **더 쉬워 보이는 길**이 있어서 그쪽으로 감

## 결론

에이전트에게 도구를 줄 때는 **무엇을 할 수 있는지**만큼 **언제 쓰지 말아야 하는지**가 중요하다.

실무에서 막는 방법:

| 방법 | 어디를 고치나 | 예시 |
| --- | --- | --- |
| ① 도구 설명에 "쓰지 말 때" 적기 | `buddy_tools.py` docstring | "이미 고른 메뉴의 이유나 감상을 묻는 질문에는 사용하지 않는다." |
| ② 시스템 프롬프트에 규칙 추가 | `lv2_hands.py`의 `SYSTEM_PROMPT` | "앞서 받은 도구 결과에 대한 질문은 도구를 다시 부르지 말고 대화 기록으로 답해." |
| ③ 도구 인자 검사 | 도구 함수 본문 | 허용 목록 밖의 값이면 에러를 돌려줘서 모찌가 알아차리고 다시 시도하게 (원본 Incident Copilot의 `_ALLOWED_REGIONS`와 같은 방식) |
| ④ 필요한 도구만 그때그때 주기 | 에이전트 구성 | 질문 종류를 먼저 분류하고 맞는 도구만 메뉴판에 올림 (사이드바로 끈 것의 자동 버전) |

**연결되는 원리**: LLM은 함수 코드를 보지 못하고, 요청마다 같이 받는 **도구 설명서(이름 + docstring + 인자)**만 보고 고른다. 도구가 많고 설명이 겹칠수록 작은 모델은 더 자주 헷갈린다.
