# 실험 노트 · Lv1 기억과 환각

- 날짜: 2026-10-07
- 레벨: Lv1 말하는 동료 (튜토리얼 5~6단계 응용)
- 모델: `llama3.1:8b` (Ollama, 로컬)
- 동료: 🐹 모찌 (`buddy_config.py` 기본 성격)
- 바꾼 변수: 이전 대화 기억하기(ON/OFF), 창의성(temperature), 성격 프롬프트 한 줄

## 실험 1 · 기본 흐름

1. "내 이름은 김코딩이야. 꼭 기억해 줘!"
2. 기억 OFF → "내 이름 뭐라고 했지?" (3번)
3. 기억 ON → "내 이름이 뭐라고 했지?"

**결과**

- 기억 OFF: 매번 "내 이름은 모찌야!" — 내 이름을 모찌라고 답함
- 기억 ON: "너의 이름은 김코딩이야!" — 맞힘 (기억 OFF 때의 오답 3개도 같이 보내졌는데도)

**왜?**

- 기억 OFF일 때 LLM이 받은 건 `system(너의 이름은 모찌)` + `human(내 이름 뭐라고 했지?)` 뿐 → 김코딩 정보가 아예 없음 → 눈앞의 유일한 이름 '모찌'를 끌어다 씀
- 기억 OFF 동안의 오답은 보내지지 않음. 모찌가 '계속 거론'된 게 아니라 매번 system에서 한 번씩 본 것
- 기억 ON일 때는 역할 표시로 구분: system의 "**너의** 이름=모찌"(assistant 자신) vs human의 "**내** 이름=김코딩"(user)
- LLM은 이름이 몇 번 나왔는지 세는 게 아니라 **누가, 누구에 대해 한 말인지**를 보고 판단하려는 경향이 있음 (단, 보장은 아님 → 실험 2)

## 실험 2 · 모찌가 흔들림 (오답에 의한 기억 오염)

1. 🧹 대화 지우기 → "내 이름은 김코딩이야"
   - 🐹 "김코딩님! 반가워요! 모찌라고 불러도 되죠?" ← 시작부터 누가 누구인지 헷갈림
2. 기억 OFF → "내 이름이 뭐야?"
   - 🐹 "그냥 내 이름은 모찌야! 신입이구나, 잘 부탁해!"
3. 기억 ON → "내 이름이 뭐라고?"
   - 🐹 "어? 내가 뭘 알려줬어? 내 이름은 모찌야!" ← 실패

**왜?**

- **직전 오답의 영향**: 마지막 assistant 답 "내 이름은 모찌야!"가 질문 바로 앞에 있음. 작은 모델은 최근 문장, 특히 자기가 방금 한 말을 따라가는 경향이 강함
- **'내'의 모호함**: 오답 속 "**내** 이름은 모찌야" 패턴이 대화 안에 박힘. 한국어 '내'는 말하는 사람에 따라 대상이 바뀌는데 8B 모델은 자주 놓침
- **질문 신호 약화**: "뭐라고 **했지**?"(과거 발언을 찾으라는 신호) → "뭐라고?"(신호 약함)
- **시스템 프롬프트의 닻**: 매번 맨 앞의 "너의 이름은 모찌"
- **temperature 0.7의 무작위성**: 실험 1의 성공도 이번 실패도 일부는 운

## 실험 3 · 변수 분리

| 조건 | 관찰 | 해석 |
| --- | --- | --- |
| 기억 ON + 창의성 0 | 이름을 맞힘 | 대화 속 근거("내 이름은 김코딩")가 있고, 창의성 0은 가장 확률 높은 답만 고름 → 근거를 따라감 |
| 기억 OFF + 창의성 0 | 지어내지 않고 "모른다". 모찌라고도 안 함 | 근거가 없을 때 가장 확률 높은 답이 "모른다"였음. 무작위성이 없어 엉뚱한 쪽으로 새지 않음 |
| 대화 지운 뒤 기억 ON + 창의성 ↑ | 환각 증가 | 2등·3등 단어도 뽑힘 → 그럴듯한 오답이 섞이고, 그 오답이 다시 기억에 쌓여 스스로 강화 |
| 성격에 "사용자와 모찌는 다른 사람" 추가 + 창의성 중간 | 기억과 상관없이 환각 감소 | 헷갈리던 '내/너' 관계를 프롬프트가 명시 → 모델이 추측할 부분이 줄어듦 |
| 창의성 ↑ + 기억 OFF | 환각 최대 | 근거 없음 + 무작위성 → 지어낼 조건이 다 갖춰짐 |

추가한 프롬프트 예시 문구: "사용자가 '내'라고 하면 사용자 본인을 뜻한다. 너(모찌)와 사용자는 다른 사람이다."

## 결론

환각은 세 가지가 겹칠 때 커진다.

1. **근거 부족** — 필요한 정보가 입력에 없음 (기억 OFF) → 대책: 대화 기억, RAG로 근거 넣어주기 (Lv4)
2. **모호함** — 누가 누구인지, 무엇을 묻는지 불분명 → 대책: 시스템 프롬프트에 규칙 명시
3. **무작위성** — temperature가 높음 → 대책: 정확성이 필요한 작업은 낮게 (이 앱 Lv2 이후는 0.3)

**주의**: 창의성 0은 '정답'이 아니라 '매번 같은 답'을 보장한다. 근거가 틀렸거나 프롬프트가 모호하면 매번 똑같이 틀린다.
→ 창의성 0 = 안정성 / 근거·프롬프트 = 정확성

**실무 교훈**: 이상한 답이 한 번 나오면 그 오답이 대화 기록에 남아 이후 답을 오염시킨다. 그래서 챗봇이 꼬이면 대화를 이어가기보다 새로 시작하는 게 낫다.
