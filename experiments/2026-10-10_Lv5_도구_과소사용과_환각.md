- 레벨: Lv5 출근하는 동료 (튜토리얼 4단계 "계산 + 기억")
- 모델: `llama3.1:8b` (Ollama, 로컬) · Lv5 에이전트 temperature 0.3 (코드 고정)

- 관련 메모: `my_notes/점심_맛집.md` — "팀 회식은 보통 '불판 고깃집'에서 한다. 6명 이상이면 이틀 전에 예약해야 한다."
- 비교 노트: [2026-10-09_Lv2_도구_과잉사용.md](2026-10-09_Lv2_도구_과잉사용.md) (반대 방향의 실수)

## 관찰

질문: "회식 6명이고 1인당 32,000원이면 총 얼마야? 예약은 언제까지 해야 돼?"

- 🔧 도구 사용 기록: `calculate ← {"expression": "(32000 * 6)"}` → `192000` **(1번뿐)**
- 🐹 답: "예약은 2023년 12월 22일까지야."
- 👀 보낸 메시지 13개

**정답**: "총 192,000원이야! 메모 보니까 6명 이상이면 **이틀 전에** 예약해야 한대~찌."
→ 필요한 도구: `calculate` + `search_my_notes` (날짜로 답하려면 `get_now`까지 3개)

## 한 턴에 실수가 세 번 겹침

| 실수 | 내용 | 원인 |
| --- | --- | --- |
| ① 도구 과소 사용 | 계산만 하고 메모 검색을 안 함 | 작은 모델은 요청이 여러 개 섞이면 **도구 하나 쓰고 "끝났다"고 판단**하는 경향. 에이전트 루프상 두 번째 도구를 부를 기회는 있었지만 스스로 멈춤. "예약은 언제까지"만으로는 메모를 찾아야 한다는 신호가 약함 (규칙이 `점심_맛집.md`에 있다는 걸 모름, 도구 설명에 "회식"이 없음) |
| ② 날짜 환각 | "2023년 12월 22일" — 근거 없는 구체적 날짜 | "언제까지"는 날짜 형태의 답을 기대하게 만듦 → 근거가 없자 그럴듯한 날짜 생성. **2023년**은 모델 학습 데이터 시점의 흔적 (`get_now`도 안 불러서 오늘 날짜를 모름). 시스템 프롬프트의 "지어내지 마"를 어긴 전형적 환각 |
| ③ 부분 답변 | 192,000원을 구해 놓고 최종 답에서 빠뜨림 | 작은 모델은 여러 질문 중 **마지막 것에 쏠리는** 경향 |

## Lv2 노트와 비교

| | Lv2 도구 과잉 사용 | Lv5 도구 과소 사용 (이번) |
| --- | --- | --- |
| 상황 | 도구가 필요 없는 질문 ("왜 짬뽕이야?") | 도구가 2~3개 필요한 질문 |
| 모찌의 실수 | 필요 없는 도구를 억지로 씀 | 필요한 도구를 덜 씀 |
| 공통 원인 | 도구 선택을 LLM이 판단 → 작은 모델은 판단이 흔들림 |
| 공통 결과 | 질문에 제대로 답하지 못하고, 근거 없는 내용으로 채움 |

→ 에이전트의 품질은 "도구가 있느냐"보다 **"LLM이 도구를 언제, 몇 번 쓸지 제대로 판단하느냐"**에 달려 있다.

## 사례 2 · 장기 기억이 있는데 안 찾음 (튜토리얼 6단계)

- 날짜: 2026-10-10
- 상황: 5단계에서 "내일 오전 10시에 스프린트 회고 있어. 기억해 줘" → `save_memo`로 저장
  → 6단계 ▶ 해보기로 **대화를 지운 뒤** "내일 일정 뭐였지?"

### 관찰

- 🔧 도구 사용 기록: `get_now ← {"": ""}` → `2026-10-10 (토) 01:21` **(1번뿐, 메모 검색 없음)**
- 🐹 답: "내일은 2026-10-11 (일)이야!"
- 👀 보낸 메시지 5개: system, human, ai(도구 요청), tool, ai → **지난 대화 없음 (단기 기억 비어 있음, 의도대로)**
- `my_notes/메모장.md`에는 메모가 정상 저장돼 있었음:
  ```
  - [2026-10-10 01:20] 내일 오전 10시에 스프린트 회고 있어
  ```

**정답**: "내일 오전 10시에 스프린트 회고 있어~찌!" (`search_my_notes`로 메모장에서 찾았어야 함)

### 해석

| 구분 | 내용 |
| --- | --- |
| 단기 기억 | 대화를 지웠으니 비어 있는 게 정상. 이 단계는 단기 기억 없이 **장기 기억(메모)으로 찾을 수 있는지** 보는 시험 |
| 장기 기억 | 데이터는 제대로 남아 있음 → **저장 문제가 아니라 검색을 안 한 문제** |
| 도구 선택 실수 | 질문의 "**내일**"이 시스템 프롬프트의 "시간·요일은 get_now"와 강하게 맞아떨어짐. "일정", "뭐였지?"(예전에 들은 걸 떠올리라는 신호)는 메모 검색으로 연결하지 못함 |
| 답의 성격 | 날짜 자체는 도구 결과로 계산한 사실. 다만 **"내일 일정이 뭐야?"를 "내일이 며칠이야?"로 바꿔 읽고** 다른 질문에 답함 (질문 바꿔치기) |
| 사소한 버릇 | `get_now({"": ""})`처럼 인자 없는 도구에 빈 인자를 넣음. 결과에는 영향 없음 |

→ 사례 1과 같은 **도구 과소 사용** 패턴. 질문 속 특정 단어 하나가 도구 선택을 끌고 감.

### 덤으로 발견: 메모장에 남은 잡음

```
- [2026-10-09 19:07] 오늘도 힘내!
```

Lv2 튜토리얼 7단계("응원 한마디만 해 줘")에서 모찌가 필요 없는 `save_memo`를 써서 응원 문구를 저장해 버림.
→ Lv2 노트의 **도구 과잉 사용**이 실제 장기 기억 데이터에 흔적을 남긴 사례. 이런 잡음이 쌓이면 검색 품질도 떨어진다.

### 고치는 방법에 대한 결정

- **채택하지 않음**: 시스템 프롬프트에 "'~였지?', '기억나?'처럼 예전 일을 물으면 반드시 search_my_notes부터 써"를 넣는 방법
  - 이유: 특정 표현마다 도구를 강제하면 **작업할 때 제약이 많아짐** (다른 도구가 맞는 상황에서도 메모 검색부터 하게 됨)
- 대신 사용자가 질문할 때 신호를 분명히 주는 쪽으로 관찰 → 아래 실험
