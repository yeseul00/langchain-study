# 4단계 · RAG: 우리 팀 자료로 답하게 하기

## 목표

- 장애 기록을 **벡터 저장소**에 넣고 의미로 검색한다.
- 검색 결과를 프롬프트에 붙여 답하게 하는 **RAG**를 직접 만든다.
- 검색을 **에이전트의 도구**로 만들어, 에이전트가 알아서 검색·조회하는 **미니 Incident Copilot**을 완성한다.

## 실행 순서

```bash
python 04_rag/step1_vector_search.py      # 저장하고 검색하기
python 04_rag/step2_simple_rag.py         # 검색 결과로 답하기 (RAG)
python 04_rag/step3_incident_copilot.py   # 에이전트 + RAG (대화형)
```

## 파일 구성

| 파일 | 역할 |
| --- | --- |
| `data/incidents.json` | 가짜 과거 장애 기록 10건 |
| `data/runbooks.json` | 대응 절차(런북) 6개 |
| `knowledge.py` | 장애 기록을 벡터 저장소에 넣는 공통 코드 |

## 핵심 개념

### RAG의 두 흐름

```
[① 넣기 — 한 번만]
장애 기록 ─▶ 임베딩 모델 ─▶ 벡터 ─▶ 벡터 저장소

[② 묻기 — 질문할 때마다]
질문 ─▶ 임베딩 ─▶ 벡터 저장소에서 비슷한 기록 검색 ─▶ 프롬프트에 붙임 ─▶ LLM 답변
```

어느 흐름에서도 **LLM을 학습시키지 않습니다.** 자료가 바뀌면 ①만 다시 하면 됩니다.

### 단순 RAG vs 에이전트 RAG

| | step2 단순 RAG | step3 에이전트 RAG |
| --- | --- | --- |
| 무엇을 검색할지 | 코드가 고정 | LLM이 판단 (필터 포함) |
| 몇 번 조회할지 | 1번 고정 | 필요한 만큼 (검색 → 런북 → 담당자) |
| 장점 | 빠르고 예측 가능 | 상황에 맞게 유연 |
| 단점 | 융통성 없음 | 느리고, 작은 모델은 실수가 잦음 |

### `metadata`와 필터

`Document`의 `page_content`는 임베딩(의미 검색) 대상이고, `metadata`(서비스·리전 등)는 조건 필터용입니다.
"부산 리전 결제 장애"처럼 물으면 에이전트가 `region="kr-busan"` 필터를 직접 채웁니다.
