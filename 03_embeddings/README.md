# 3단계 · 임베딩: 문장의 "뜻"을 숫자로

## 목표

- **임베딩**이 문장을 숫자 목록(벡터)으로 바꾸는 것임을 확인한다.
- 뜻이 비슷한 문장끼리는 벡터도 가깝다는 걸 **코사인 유사도**로 확인한다.
- **키워드 검색이 놓치는 문장을 의미 검색은 찾는다**는 걸 비교해 본다.

## 실행

```bash
python 03_embeddings/step1_embedding_basics.py
python 03_embeddings/step2_keyword_vs_semantic.py
```

## 핵심 개념

### 임베딩 = 문장을 "의미 지도" 위의 좌표로 바꾸기

```
"결제가 자꾸 실패해"        → [0.012, -0.087, 0.143, ... ]  (1024개 숫자)
"카드 승인 오류율이 올라감"  → [0.015, -0.079, 0.151, ... ]  ← 좌표가 가깝다
"검색 결과 순서가 이상해"    → [-0.120, 0.044, -0.031, ... ] ← 멀리 떨어져 있다
```

- 지도가 2차원(x, y)이라면, 임베딩은 1024차원(bge-m3 기준) 지도입니다.
- **같은 단어를 쓰지 않아도** 뜻이 비슷하면 가까이 놓입니다. 이게 키워드 검색과의 차이입니다.

### 코사인 유사도

두 벡터가 **같은 방향을 가리키는 정도**. 1에 가까울수록 비슷하고, 0에 가까울수록 관련이 없습니다.
계산식은 `step1`에 파이썬 몇 줄로 직접 구현돼 있습니다.

### 중요: 이건 "학습"이 아니다

임베딩 모델은 이미 다 학습된 상태로, 문장을 좌표로 **변환만** 합니다.
4단계의 RAG도 모델을 새로 학습시키지 않습니다. 자료를 좌표로 바꿔 저장해 두고 찾아 쓸 뿐입니다.
